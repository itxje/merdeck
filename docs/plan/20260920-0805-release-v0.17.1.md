file names in a wide listing, and a heading chosen from the Markdown contents list stopped at the bottom of
the view instead of the top. Native verification on `main` passed for that commit. The owner asked to release.

1. Choose `v0.17.1`: two corrections to behaviour shipped in v0.17.0, no new behaviour and no contract change,

2. Create the annotated tag on the verified commit and push it alone.
3. Monitor the tag workflow until `merdeck.tar.gz` and `SHA256SUMS` are published, then verify the checksum
   against the downloaded archive rather than trusting the workflow's own result.
4. Record the release outcome in the changelog and task documentation.

  than a hazard.

Tag and release automation only; no source change.

  wrong place on the deployed instance.
