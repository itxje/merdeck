## Context

The owner reports that released v0.19.3 still cannot scroll Files on first open in iPhone Safari. The next candidate removes a forced search-input focus and the ineffective overflow overrides. A new touch-open browser regression fails on v0.19.3 and passes on the candidate. Local ARM64/overlay `check:ci` passes on clean commit `bfe0a9b`, but native iOS touch is unverified and Linux x64/ext4 release acceptance is pending.

## Proposal

1. Push a clean release candidate on main.
2. Require the GitHub main workflow to pass native Linux x64/ext4 source and executable acceptance on the exact candidate commit.
3. Create and push annotated tag v0.19.4 on that commit. Require the tag workflow to verify and publish.
4. Download the release archive and checksum, verify both and the embedded version/commit, and record the result. Ask the owner to test the affected iPhone after deployment before closing the scrolling bug.

## Risks

- Browser automation cannot reproduce native iOS touch. Publishing makes the candidate available for affected-device testing but does not establish that the gesture works.
- Native verification or publication may fail. Retain evidence and fix or rerun the identical candidate; do not move a published tag.
- Release publication does not update the independently running service.

## Scope

Release tracking, main push, native verification, tag publication and artifact verification. No application source or live service deployment changes.

## Alternatives

- Holding the release would prevent validation of the corrected build on the owner's phone.
