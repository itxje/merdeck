## Outcome

Published `v0.14.4`. Native verification on `main` passed as
[run 35365581159](https://github.com/itxje/merdeck/actions/runs/35365581159).

The tag workflow's first attempt failed in `files.spec.ts` ("the explorer creates, renames, moves and deletes
files and folders inside the project") with `Unexpected HTTP 503 /api/diagrams/directory`. That case holds a
directory request open on purpose to assert the explorer's busy state, and `unavailable` is the repository's
fallback for a filesystem call that fails for an unclassified reason, so a loaded runner can produce it. The
same commit had already passed the identical gate on `main`, and the local suite passed 71/71, so the failure
was treated as an infrastructure flake and the job was rerun rather than the code changed. The rerun passed
both `verify` and `publish` as [run 35366550282](https://github.com/itxje/merdeck/actions/runs/35366550282).

Downloaded `merdeck.tar.gz` (1382888 bytes, 97 archived files) and `SHA256SUMS`; `sha256sum -c` reports OK.

If that spec flakes again on a release tag, it needs its own task: either the held-request window or the
repository's unclassified-error mapping deserves a closer look.
