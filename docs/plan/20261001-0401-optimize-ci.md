## Context

Every main, pull-request and version-tag event currently invokes full native verification. The v0.19.17 release waited for a main run before starting the same gate on its tag. Each gate also ran two independent browser suites sequentially. Documentation-only pushes repeat all heavy checks.

## Proposal

Classify changed paths with Git and an explicit documentation allowlist. Keep an always-present verification status, but bypass heavy setup for documentation-only changes. Always select complete native acceptance for version tags, workflow dispatch and the explicit native-readiness branch. Ordinary source changes run the source portion of the gate. Report source-only success distinctly from native artifact acceptance and forbid source-only verification for real release tags.

Build the executable and bundle into separate owned staging directories, then run their complete smoke suites concurrently with isolated browser output directories. Await both successes or failures before moving artifacts or returning, so cleanup completes even if one suite fails. Preserve the normal full check:ci --native gate for release delivery, same-run artifact IDs, immutable action pins and tag-only publishing.

## Risks

Change classification must include both paths of renames/deletions, pull-request merge bases and all commits in a push. Tags and manual verification must bypass path filtering. Source-only proof must never certify a release. Concurrent browser runs require isolated fixture, service and output ownership, and all failures must propagate after cleanup.

## Scope

CI workflow, event classification, hosted mode selection, check orchestration, relevant regression tests, README and decision/task records. No application behavior or dependency changes.

## Alternatives

Cross-run artifact caching requires additional provenance and expiry handling. Separate source and native artifact stages removes most expensive duplication without consuming earlier build artifacts. Retaining full sequential verification for every documentation push preserves the current unnecessary runtime.

## Annotations

The owner authorized optimization. Final release acceptance still requires the complete normal Linux x64/ext4 gate with separate refusal storage.
