## Context

Two changes are on `main` as commit `f1534f3`, neither of which reaches the owner's instance until a release.
`c6a4de2` gives the AI file editor's conversation room on a phone and removes the approval step end to end,
including the HTTP route, the event and the request schema. `f1534f3` moves the assistant toggle out of the
phone overflow menu into the header and rebuilds the Markdown view switch, whose tabs overflowed their own
list into the header and sat flush against the edge of the screen. The owner asked to release.

## Proposal

1. Choose `v0.18.0`: the agent HTTP surface loses a route and an event, which is a contract change rather
   than a correction, so a minor bump rather than a patch.
2. Create the annotated tag on the commit native verification passed for, and push it alone.
3. Monitor the tag workflow until `merdeck.tar.gz` and `SHA256SUMS` are published, then verify the checksum
   against the downloaded archive rather than trusting the workflow's own result.
4. Record the release outcome in the changelog and task documentation.

## Risks

- Removing the approval route is visible to any client that called it. The only client is this repository's
  own panel, which no longer does, and the service refuses an unknown path rather than misbehaving.
- A tab that stored a transcript containing an approval starts with an empty transcript after the upgrade.
  The conversation itself is memory-only on the service and does not survive a restart in any case.

Tag and release automation only; no source change.
