## Context

The interface refresh is integrated into `main` as commit `329b84e`: one five-step type ramp with an 11px
floor and monospace path strings, a low-chroma teal accent with a warning amber beside the existing red, an
explorer folded into one action rail with the type filter inside the search field, explorer rows that wrap
instead of middle-truncating, and a phone layout with the assistant as a bottom sheet, a header overflow menu
and a three-way bottom bar. Native verification on `main` passed for that commit. The owner asked to release.

## Proposal

1. Choose `v0.17.0`: new interface behaviour across five tracks, no contract or storage change, so a minor
   bump.
2. Create the annotated tag on the verified commit and push it alone.
3. Monitor the tag workflow until `merdeck.tar.gz` and `SHA256SUMS` are published, then verify the checksum
   against the downloaded archive rather than trusting the workflow's own result.
4. Record the release outcome in the changelog and task documentation.

## Risks

- The owner's deployment follows the stable channel automatically, so the release reaches that instance within
  minutes of publication. This release changes what the interface looks like on every screen, which is visible
  to anyone using that instance immediately.

## Scope

Tag and release automation only; no source change.

## Alternatives

- Releasing each track as it landed would have put four intermediate interfaces in front of the owner's
  instance, including one where the accent existed without the density and wrapping work that balances it.

## Outcome

Verification passed on `main` for `329b84e`, the tag workflow published `merdeck.tar.gz` and `SHA256SUMS` on
2026-09-20 at 06:32:15Z, and `sha256sum -c` reports OK on the downloaded archive.
