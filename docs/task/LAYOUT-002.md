# LAYOUT-002 Resize and collapse the source and preview panes

- **status**: completed
- **priority**: P2
- **owner**: Frontend maintainer
- **createdAt**: 2026-09-10 18:00

## Description

The project owner asked on 2026-09-10 for the divider between the source editor and the preview to be draggable, for example to give the preview more room, and for the source pane to be collapsible. Acceptance: at desktop and tablet widths the divider can be dragged with a pointer and moved with the keyboard to resize both panes within sensible minimum widths; the source pane can be collapsed and restored with visible controls; the chosen layout survives a reload in the same browser; narrow screens keep the existing Source/Preview tabs; saving, drafts, preview navigation and label editing are unchanged.

## ActiveForm

Making the source and preview split resizable and collapsible.

## Notes

- Investigation: `web/src/features/workspace/workspace.tsx` renders `.panes` as a CSS grid (`web/src/index.css`: `minmax(300px, .85fr) minmax(340px, 1.15fr)`, and `minmax(280px, 1fr) minmax(320px, 1.1fr)` below 1100 px) holding the source `section` and the `Preview` section. At 700 px and below `.panes` becomes flex and `data-pane` hides one section behind the Source/Preview tabs. There is no divider element. The shadcn base-nova registry ships a `resizable` component built on `react-resizable-panels` (latest stable 4.12.4 on npm, checked 2026-09-10), which is the stack's sanctioned way to add resizable panel groups. The browser suite only asserts that narrow layouts do not overflow horizontally.
- Proposal (owner request, routine layout defaults): add the registry `resizable` component through the project's shadcn CLI (4.21.0, the current release) with `react-resizable-panels` pinned exactly at 4.12.4, and replace the `.panes` grid with a horizontal panel group holding a collapsible source panel (default 42.5%, minimum 240 px, collapsing to a 40 px rail when dragged below its minimum) and a preview panel (minimum 320 px) separated by a labelled handle. The handle keeps the library's pointer, keyboard and double-click-to-reset behaviour. A "Hide source" button in the source heading collapses the panel and a "Show source" button on the rail restores it; the collapsed textarea stays mounted so drafts, scroll and selection survive. The layout is remembered in `localStorage` through the library's `useDefaultLayout`. At 700 px and below the handle, rail and collapse button are hidden and the existing Source/Preview tabs show one full-width pane regardless of the desktop layout. The prototype stays unchanged and keeps its fixed split.
- Implementation: `web/src/shared/components/ui/resizable.tsx` comes from the registry through the project's shadcn CLI (then formatted by the lint fixer), and `react-resizable-panels` is pinned exactly at 4.12.4 in `web/package.json` and `web/bun.lock`; a frozen install with Bun 1.4.2 reports no changes. `workspace.tsx` renders the panes as a horizontal `ResizablePanelGroup` (`.panes`) with `#source-panel` (collapsible to a 40 px rail, minimum 20%, default 42.5%) and `#preview-panel` (minimum 30%) around a `ResizableHandle` labelled "Resize source and preview"; `useDefaultLayout({ id: 'merdeck-panes', storage: localStorage })` restores and saves the layout. The source heading gains a "Hide source" button and the collapsed rail a "Show source" button, both using the panel's imperative API, and `onResize` tracks the collapsed state. The collapsed source section is marked `data-collapsed` and stays mounted. `index.css` drops the old grid and lets the panel slots fill their panels; at 700 px and below it hides the handle, rail and collapse button, forces both panels to full width over the library's inline flex values and shows only the tabbed pane.
- Pitfall: the first browser run of the new spec failed after collapsing the source on desktop and narrowing the viewport. The section used the `hidden` attribute, and Tailwind's preflight declares `[hidden]` as `display: none !important`, which beat the narrow-screen override and left the Source tab empty. The collapsed state now uses a data attribute instead.
- Pitfall: the next full browser run failed in the narrow file drawer case. With pixel minimums (240 px and 320 px), a 390 px viewport could not satisfy both panels, so the library collapsed the source panel, saved that layout and kept it collapsed after the viewport widened again. Percentage minimums (20% and 30%) always fit, so narrowing the window no longer collapses the source.
