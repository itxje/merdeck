## Description

Track 5 of the UI refresh proposal in `docs/plan/20260919-1736-ui-refresh-plan.md`: dock the AI file
editor to the bottom edge on phones instead of covering the document, start it closed under the
phone breakpoint without disturbing a desktop preference, collapse the no-provider state to one
dismissible line, move the theme switch, the assistant toggle and sign-out into a header overflow
menu, replace the top pane tab strip with a bottom bar holding the project-files control beside the
source and preview tabs, and raise every interactive control under the breakpoint to a 44px target.

### A shared test helper conflicts with this track's own requirement

`web/src/test/e2e/support.ts`'s `login()` helper asserts the "Log out" button visible immediately
after authenticating, at whatever viewport the caller has already set. Moving sign-out into the
overflow menu below the phone breakpoint — this track's own explicit requirement — means that
assertion now fails for every spec that authenticates while already narrower than 700px, independent
of anything this track's own files changed afterward. `support.ts` is not one of the files this task
can edit.

Confirmed against the complete existing browser suite: this reaches four cases already in the
repository, each authenticating while already narrower than 700px — one in `directory.spec.ts` and
all three in `drawer.spec.ts`. None of these are fixable from within their own files, since the
failing assertion runs inside the shared helper before the calling test regains control.

Every case this task added or extended instead authenticates at a wide viewport first and narrows
afterward — the same pattern the pre-existing, still-passing specs in this file already use — so
none of this task's own new coverage depends on the fix below.

Proposed fix, for whichever record owns `support.ts`: change `login()`'s post-authentication check to
something reachable at every viewport, for example the absence of the access-token field, or a
`getByRole('button', { name: 'Open project files' })` visibility check (present at every width once
signed in, per this same track), rather than "Log out" specifically.
