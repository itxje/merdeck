# LAYOUT-003 Redesign the application header controls

- **status**: completed
- **priority**: P2
- **owner**: Frontend maintainer
- **createdAt**: 2026-09-11 02:05

## Description

The project owner asked on 2026-09-11 for the application header to be redesigned. The controls on the right (an outlined "Theme: system" text button beside bare refresh and log-out icons) look inconsistent, and the "/ Project files" label on the left suggests file management that does not exist. Acceptance: the header shows the brand and a small, consistent set of controls; the theme preference is visible and can be changed in one step with a pointer or the keyboard; every icon-only control has an accessible name and a visible hint; the refresh action sits with the file list it refreshes; nothing in the header implies an unavailable feature; the sign-in page, the narrow drawer and tab layouts, saving, drafts and the logout confirmation are unchanged.

## Notes

- Investigation: `web/src/features/workspace/workspace.tsx` renders the header as the brand mark and "Merdeck", then a static `.project-crumb` ("/", a folder icon and "Project files") that is neither a link nor a menu. On the right, `ThemeToggle` (`web/src/app/theme-toggle.tsx`) is an outline text button that cycles system → light → dark and prints the raw preference, followed by ghost icon buttons "Refresh project" (`state.refresh`, which invalidates every query except the review) and "Log out" (which opens the confirmation dialog). No icon button shows a hint. `TooltipProvider` is already mounted in `web/src/app/providers.tsx`, but no tooltip is used yet.
- File management: the explorer (`web/src/features/workspace/file-tree.tsx`) lists, filters and opens supported files and Markdown blocks, and the API offers only tree, document, revision and source-save routes. Creating, renaming, moving and deleting files are outside the delivered scope: external tools edit the project directly and saves never recreate a deleted file. The crumb therefore advertised a capability the product does not have. File operations would be new scope that needs its own proposal.
- Tests address these controls by accessible name: `Theme:` in `workspace.spec.ts`, `Refresh project` in the workspace, save-race, tree and acceptance specs, and `Log out` in `support.ts` and `workspace.spec.ts`. `web/src/app/theme.test.tsx` covers the cycling button.
- Proposal (owner request, routine visual defaults): remove the static crumb so the header keeps only the brand on the left. Replace the text theme button with a compact segmented switch of three icon toggles (Light, Dark, System) built from the base-nova registry `toggle-group`, added through the project's shadcn CLI; the pressed toggle shows the current preference and the selection cannot be cleared. Keep "Log out" as a ghost icon button after a thin divider. Move the refresh button into the explorer heading beside the file count as "Refresh files"; it keeps its behaviour and is also available in the narrow file drawer. Icon-only controls get tooltips. Update the unit and browser tests and the architecture description. The prototype stays unchanged and needs-review.
- Implementation: `web/src/shared/components/ui/toggle.tsx` and `toggle-group.tsx` come from the base-nova registry through the project's shadcn CLI 4.21.0 without dependency changes (`@base-ui/react` 1.8.0 already provides the primitives) and were formatted by the lint fixer. The group uses the React 19 context forms (`<Context value>` and `React.use`) that `web/src/app/theme.tsx` already uses, and `toggleVariants` joins `buttonVariants` among the allowed non-component exports in `web/eslint.config.ts`. `web/src/app/theme-toggle.tsx` renders a toggle group labelled "Theme" with "Light theme", "Dark theme" and "System theme" icon toggles (sun, moon and monitor), each with a tooltip; the pressed toggle reflects the stored preference, and releasing it is ignored so one preference always stays selected. `workspace.tsx` drops the crumb and the header refresh button and, when signed in, shows a divider and a "Log out" icon button with a tooltip. `file-tree.tsx` takes a `refresh` callback and renders a "Refresh files" icon button with a tooltip after the filter input, in both the sidebar and the narrow drawer. `index.css` removes the crumb rules and the old narrow text-button override, draws the switch as a bordered 32 px segment of 26 px toggles (44 px at 700 px and below), lays out the filter row as a flex row and extends the narrow 44 px touch-target rules to tooltip-wrapped buttons. The theme unit test covers the pressed state, keyboard operation, a repeated press and persistence. The new `header.spec.ts` covers the header contents, control and icon sizes, tooltips, the preference across a reload, refresh placement and focus order, and 390 px and 360 px widths. The other browser specs use the renamed controls. `docs/architecture.md` describes the header and now lists the pane layout among the persisted browser settings.
- Pitfall (refresh placement): the first browser run placed "Refresh files" in the explorer heading. The narrow drawer then opened with focus on that button instead of the filter input, which failed the drawer spec's focus contract. The button now follows the filter input, so the drawer still focuses the filter first, Shift+Tab still reaches Close, and focus order matches visual order.
- Pitfall (icon sizes): the first screenshots showed 24 px icons inside icon buttons. The registry class strings contain `[&_svg:not([class*='size-'])]:size-4`. When the lint fixer converted them to single-quoted strings it escaped the inner quotes, and Tailwind then generated a class selector containing literal backslashes that never matched the runtime class. Every icon in base-nova buttons, toggles, selects, menus, alerts and tabs therefore fell back to lucide's 24 px default. The six affected components now use `[class*="size-"]`, the built stylesheet contains the matching selector, and icons render at 16 px (12 px in extra-small buttons). This also returns the preview zoom controls and the pane collapse icons to their intended sizes.
- Pitfall (data-slot): a tooltip trigger that renders a button replaces that button's `data-slot` with `tooltip-trigger`. Selectors on `[data-slot="button"]` or `[data-slot="toggle-group-item"]` therefore missed those controls: the switch toggles kept 32 px heights and narrow Log out and Refresh buttons lost their 44 px targets. The switch and refresh rules now select elements, and the narrow touch-target rules include `[data-slot="tooltip-trigger"]`.
- Related documentation correction: two statements left over from before SESSION-001 still said sessions end on restart, in the HTTP contract paragraph of `README.md` and the private token paragraph of `docs/deployment-domain.md`. Both now say that sign-ins survive a restart with the same token and root until they expire and that a new token signs every browser out.
