### Investigation and proposal (2026-09-07)

Claimed before investigation as Quality maintainer and re-read both tracking files. Implementation and routine corrections use the original 2026-09-07 authorization recorded in PLAN-001; no subsequent design approval is inferred.

Existing coverage consists of the source-discovered file/API bridges, practical consecutive-save tests and four real browser flows. Browser startup currently requires manually configured services, the config retains traces by default, and error collection only covers the first flow. Existing domain/API tests already cover concurrent writes, injected atomic I/O failures, procfs/root/symlink substitution, typed errors, authentication and exact Markdown bytes. These should be reused rather than duplicated. Current writable acceptance is overlayfs; the host-shared checkout must reject writes. Ordinary native storage, binary-only delivery and remote execution remain separate gates.

Proposal: add a dependency-free TypeScript acceptance runner using explicit canonical fixture parents, observed filesystem/device evidence, private token files, owned tmux service windows, event-driven bounded readiness and cleanup. Retain an explicit existing-service URL mode for later executable checks. Extend browser coverage for actual standalone saves, clean/dirty external changes, obsolete loads, source byte limits and settled accessibility/rendering states. Apply error/resource auditing to every browser test, disable credential-bearing traces/artifacts, record exact checks and screenshots, and document reusable local/CI contracts. Production feature files and dependency versions remain unchanged. Any confirmed functional defect will be recorded with its useful failing test and returned for focused correction.

Risks: controlled API delays test races without asserting private state; all edits require disposable sample roots. Read-only/unreadable states may require existing fault-injection tests because local directory permissions are not enforced. Renderer restrictions and bundle-size advisory remain explicit. Coverage scope/exclusions and unsupported/native gaps will be reported honestly.

No high-confidence production defect was found in this bounded acceptance audit.
