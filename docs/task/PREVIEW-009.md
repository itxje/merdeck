# PREVIEW-009 Accept bidirectional sequence messages and bounded front matter configuration

- **status**: completed
- **priority**: P2
- **owner**: Frontend maintainer
- **createdAt**: 2026-09-12

## Description

The project owner brought a directory of eighteen diagrams. Six previews stay empty for two distinct policy reasons, and every one of the eighteen parses without error under the pinned Mermaid. Three sequence diagrams use the bidirectional message arrow, `A<<->>B`, whose leading angle brackets meet the global refusal of `<`; flowcharts already carve out `<--`, `<==` and `<-.`, but no other family does. Three Gantt charts open with a front matter block carrying `title` and a `config` key, and the policy admits exactly one `title` key, so the block fails to match and its fences then meet the refusal of `---`. Acceptance: a sequence diagram may use `<<->>` and `<<-->>`; a front matter block may carry a bounded `config` alongside its title; every construct the policy refuses today that neither rule names stays refused; and Mermaid still receives the original source.

- Investigation (2026-09-12): front matter `config` reaches `addDirective`, the same entry a `%%{init}%%` directive uses, which is why PREVIEW-007 refused it. Mermaid sanitizes that entry twice. `sanitizeDirective` drops keys outside its own schema, drops prototype-shaped keys and bounds `themeVariables` values. `sanitize` then drops every key named in the host `secure` list at every nesting depth, plus string values containing `<`, `>` or `url(data:`. The host list already covers `securityLevel`, `htmlLabels`, `theme`, `themeVariables`, `fontFamily`, `maxTextSize`, `maxEdges`, `startOnLoad`, `suppressErrorRendering` and `secure` itself, so a front matter block cannot reach any of them. The list does not cover `themeCSS`, which Mermaid keeps as a schema key and only brace-balances, and the measurement host in `renderer.ts` sanitizes with a DOMPurify configuration that does not forbid `style`. A wholesale `config` passthrough would therefore put diagram-authored CSS into the live document. A bounded configuration that admits no string value at all closes that path by construction instead of relying on the host list.
- Investigation (2026-09-12): the existing front matter refusals in `flowchart-policy.test.ts` remain correct under a section-scoped, non-string configuration. `config` with a bare `theme` leaf, a `displayMode` key beside the title, a second block, a block after the diagram and a bare fence all stay refused without editing those cases.
