## Description

The project owner asked on 2026-09-10 whether the source editor and the preview can edit in both directions, so that diagram content can also be changed on the diagram itself. This task covers the investigation and proposal; implementation waits for the owner's decision on [PLAN-013](../plan/PLAN-013.md). Acceptance for the proposed first slice: in a flowchart preview, double-clicking a node opens an inline editor with its current label; confirming rewrites only that label in the source editor as an ordinary unsaved draft; cancelling leaves the source untouched; clicking a node selects its definition in the source editor; unsupported diagrams and nodes stay read-only with a short explanation.

## Notes

- Investigation: the preview mounts Mermaid 11.17.2 output only after `web/src/features/preview/renderer.ts` sanitises it. Element `id` attributes matching `^[\w-]+$` survive, and a live render of the demo `welcome.mmd` produced flowchart node groups `diagram-1-flowchart-Browse-0`, `diagram-1-flowchart-Select-1`, `diagram-1-flowchart-Edit-3` and `diagram-1-flowchart-Save-5`, so the source node id is recoverable for flowcharts. Mermaid exposes no source positions, and `data-*` attributes, including edge label ids, are stripped. `web/src/features/preview/source-policy.ts` already splits flowchart statements at syntax boundaries while respecting quotes and comments. The source editor is a textarea whose changes go through `state.dispatch({ type: 'edit', path, block, source })` in `web/src/features/workspace/workspace.tsx`; `Preview` receives only `source`, `title` and `onError`. Mermaid computes layout on every render, so node positions cannot be written back into the source.
- Proposal: recorded in [PLAN-013](../plan/PLAN-013.md) and presented to the owner on 2026-09-10; the owner approved the recommended scope with `proceed` the same day.
- Implementation: instead of a hand-written scanner, `renderer.ts` reuses Mermaid's own flowchart lexer (`diagram.parser.parser.lexer` from `mermaid.mermaidAPI.getDiagramFromText`) inside the serialized render queue, blanking whole-line comments so token offsets match the draft. `flowchart-labels.ts` walks those tokens per statement, skipping headers, subgraph, class and direction statements, edge text and `:::` class names, and records for each node the last labelled definition (the one Mermaid displays) or its first bare occurrence. Quoted, plain and bare labels are editable; markdown strings and property syntax are not. Writing trims each line, joins lines with the label's existing break spelling (default `<br>`), quotes text containing brackets, slashes or angle brackets, inserts `[label]` after a bare id, and refuses empty text, double quotes and backticks. Every edit re-runs `validateSource`, then parses the result and a one-node probe of the written label and accepts it only when all vertices, edges and subgraphs match except the chosen label. `preview.tsx` loads the label sites after each settled render (`data-editable` is `pending` until then and `ready` afterwards), turns a click on a node into a source selection, and opens an inline `Textarea` positioned from the node's box in diagram coordinates on double-click (Enter applies, Shift+Enter adds a line, Escape cancels, blur applies unless the value was already refused). Presses start panning only after 4 px of travel so clicks still reach nodes, and a click that ends a drag is ignored. `workspace.tsx` selects the reported range in the source textarea and dispatches accepted edits as ordinary `edit` actions.
