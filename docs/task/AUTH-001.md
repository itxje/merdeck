# AUTH-001 Open the workspace without an access token by default

- **status**: completed
- **priority**: P2
- **owner**: Backend maintainer
- **createdAt**: 2026-09-11 04:51

## Description

The project owner asked on 2026-09-11 to turn the access token sign-in page off by default, so that the workspace opens without a token. Today `MERDECK_TOKEN` is required at startup, every `/api/diagrams/*` request needs a signed session cookie obtained by posting that token, and mutations additionally need the exact Origin and a CSRF token. Acceptance for the proposed change: a loopback-only service started without a token opens the workspace directly, with no sign-in page and no Log out; a service with a token keeps today's sign-in, sessions, CSRF protection and logout; without a token, a service reachable beyond loopback refuses to start unless open access is explicitly acknowledged; Host and Origin validation, root containment, file admission and storage checks apply in both modes.

## Notes

- Investigation (2026-09-11): `src/config.ts` requires `MERDECK_TOKEN` (32–256 printable characters), and `src/app.ts` always constructs `Sessions` from it. `src/modules/auth/sessions.ts` derives the cookie signing and CSRF key from the token and the canonical root; `src/modules/auth/routes.ts` serves GET, POST and DELETE `/session`, where POST compares the token in constant time under a rate limit. `src/modules/diagrams/routes.ts` calls `requireSession` for every `/diagrams/*` request and `requireMutation` (exact Origin plus CSRF token) for saves and entry operations. `src/shared/middleware/boundary.ts` independently enforces the Host allow-list, Origin equality when supplied and same-origin fetch metadata, and the service sends no CORS headers. File access is limited by `allowedPath` to `.mmd`, `.mermaid` and `.md` files (`fileKind` throws `unsupported` otherwise) outside hidden and ignored directories. The web workspace (`use-workspace.ts`, `workspace.tsx`) derives the signed-in state from GET `/session`, locks unsaved drafts when the session disappears or changes, and shows the sign-in card or Log out accordingly. The token is also used by the configuration tests, three HTTP integration suites, the browser gate runner and service starter, the release smoke scripts, the browser login helper and three specs, and the workspace unit test. The stack decision recorded the mandatory token in place of an earlier optional-loopback proposal. The hosted instance binds 127.0.0.1 behind the nsl route; its hostname resolves to a private network address, and the ingress access controls cannot be inspected here, so a loopback bind does not show who can connect.
- Proposal: recorded in [PLAN-016](../plan/PLAN-016.md) and presented to the owner on 2026-09-11, including a separate decision on whether the hosted instance also drops its token.
- Approval: the project owner replied `proceed` on 2026-09-11 to the proposal as written and chose open access for the hosted instance as well. Implementation follows the plan directly on the main checkout.
- Implementation (2026-09-11): `src/config.ts` makes `MERDECK_TOKEN` optional (an empty value counts as unset) and adds `MERDECK_OPEN_ACCESS`. Without a token, startup requires a loopback bind address and loopback allowed origins (127.0.0.0/8, `::1` or `localhost`) unless `MERDECK_OPEN_ACCESS=true`, and the flag together with a token is rejected. `src/app.ts` creates `Sessions` only with a token, and its constructor now takes the token explicitly. The session status carries `access: 'token' | 'open'` (`SessionCapabilities` in `src/shared/contracts.ts`). With open access, GET `/session` returns the capabilities without a cookie, CSRF token or expiry, POST and DELETE answer 405 with `Allow: GET`, `requireSession` returns no session, and `requireMutation` still requires the exact Origin but skips the CSRF check. The web workspace decodes both statuses and sends `X-CSRF-Token` only for token sessions (`sessionCsrf`). With open access it hides Log out and its dialog, shows `Open access` with an open-lock icon in the status bar and runs no expiry timer. After a session identity change it refetches the session, so a service that no longer needs a token reopens the workspace with retained drafts locked for review (`reopen`, shared with sign-in). The sign-in card no longer asks for a token while the session check is pending. The browser gate starts a third built service without a token on its own sample copy and passes `MERDECK_OPEN_URL` and `MERDECK_OPEN_ROOT` to the suite; in existing-service mode both are optional and the new spec is skipped without them. `open-access.spec.ts` opens the workspace without signing in, saves an edit to disk, and finds no Log out and no cookies. README, `.env.example`, SECURITY, architecture and a stack decision addendum describe both modes.
- Pitfalls: with `exactOptionalPropertyTypes`, passing an explicit `undefined` CSRF token needs `csrfToken?: string | undefined` in the HTTP client options. Session expiry runs in an effect after the session update, so hook tests must wait for the draft lock instead of asserting it right after the update.
