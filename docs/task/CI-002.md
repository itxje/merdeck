## Description

After `main` was published, the `Verify and release` workflow failed for both published commits. The project owner asked on 2026-09-11 to fix it on `main`. Acceptance: release manifests accept the root-level brand icon that the service serves and still refuse other root paths, the embedded asset inventory matches the bytes the executable serves, and the release checks pass.

Fixing the release manifest check for the root brand icon.

## Notes

- Investigation (2026-09-11): in both runs the native `check:ci` passed its storage, source and release test stages, then `packageRelease` rejected the compiled manifest. The asset path schema in `scripts/release/manifest.ts` admits only `/index.html` and `/assets/*`, but the build also emits the root-level `/favicon.svg`, which `staticResponse` serves. A standalone `compile` without a prior build also runs only the frontend build, so it embeds a shell without the `merdeck-build` element while the executable serves the shell with it, and the recorded `/index.html` hash would not match the served bytes that the release smoke compares. `check:ci` builds through `bun run build` first, so the workflow is not affected by the second issue.
- Implementation (2026-09-11): the manifest path schema in `scripts/release/manifest.ts` now also admits exactly `/favicon.svg`, matching the paths `staticResponse` serves. `scripts/embed-assets.ts` applies `snapshotBuildAssets` to the loaded build before recording and embedding it, so the inventory holds the shell the executable serves whether or not the build output already carries its identity; a build from `bun run build` already carries it, and its bytes are unchanged. The release fixture inventory includes the icon, `package.test.ts` checks that `/favicon.ico`, `/robots.txt`, `/assets` and `/other/app.js` are still refused, and the new `embed.test.ts` compares the embedded inventory and files with the served snapshot for a shell with and without the identity.
- Verification (2026-09-11, main checkout, pinned Bun 1.4.2, inside the project tmux session): root ESLint and `tsc --noEmit` passed, and `bun run test:release` passed 20 of 20 tests across 8 files, including both new tests, after the release and CI type checks. This host lacks the strace and actionlint prerequisites, so `check:ci` was not run locally. Instead, the existing build output was compiled for `bun-linux-arm64` and packaged, and a disposable loopback run of that executable served all 94 manifest assets, including `/favicon.svg` as `image/svg+xml`, with the recorded content type, size and SHA-256, `nosniff` and a same-origin script policy. `/api/build` reported the identity carried by the served shell, and `/robots.txt`, `/favicon.ico`, `/api/missing`, `/assets/missing.js` and `/.env` returned 404. Native x64 execution and the complete `check:ci --native` remain for the push workflow.
